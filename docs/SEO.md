# SEO

How search works on this site, where each piece lives, and what to do when you
add a page. Everything here describes code that exists; anything still to be
done is in [Not done yet](#not-done-yet).

## 1. Architecture

The public site is a small set of statically prerendered pages inside the same
Next.js App Router project as the product. That split matters more than it
looks:

| Surface | Routes | Rendering | Indexable |
|---|---|---|---|
| Marketing | `/`, `/onboarding`, `/contact`, `/privacy`, `/terms` | Server / static | Yes |
| Guides | `/guides`, `/guides/[slug]` | Static, `generateStaticParams` | Yes |
| App | `/today`, `/record`, `/sessions`, `/library`, `/coach`, `/trainer`, `/practice`, `/listen`, `/dashboard` | Client, needs user data | **No** |

The app screens render nothing without one person's recordings, so they are
worthless to a crawler and are excluded by header rather than by content. The
marketing and guide pages never depend on client state, which is why they are
server components with real anchors rather than reusing the app's nav.

## 2. Indexability

`X-Robots-Tag: noindex, nofollow` is applied in `apps/web/next.config.ts` to
every prefix listed in `apps/web/src/lib/private-routes.ts`.

**This is deliberate and Search Console will report it forever.** Inspecting
`/today` returns *"Crawl allowed? Yes. Indexing allowed? No: 'noindex' detected
in 'X-Robots-Tag'"*, which is the mechanism working, not a fault. The
alternative - `Disallow` in robots.txt - is strictly worse: Google never
fetches the page, therefore never reads the `noindex`, and stays free to list
the bare URL from any link it finds.

Only inspect and submit the URLs in the sitemap. The app routes will sit
permanently under *Excluded by 'noindex' tag*, which is a category and not a
queue.

## 3. robots.txt

Generated by `apps/web/src/app/robots.ts` rather than checked in as a static
file, because the `Sitemap:` directive must be an absolute URL and only the
deploy knows its own origin (`NEXT_PUBLIC_SITE_URL`).

```
User-Agent: *
Allow: /
Disallow: /api/

Host: https://foundervoice.app
Sitemap: https://foundervoice.app/sitemap.xml
```

`/api/` is the rewrite proxy to FastAPI - JSON and audio, nothing a crawler
should spend a fetch on. Nothing else is disallowed, deliberately: CSS and JS
under `/_next/` must stay crawlable or Google cannot render the pages, and AI
crawlers (GPTBot, ClaudeBot, PerplexityBot) are allowed on purpose.

## 4. Sitemap

`apps/web/src/app/sitemap.ts`. Guides come from the `GUIDES` array, so adding a
guide adds it to the sitemap with no second edit.

Two rules that are easy to break:

- **`lastmod` must be a real edit date.** It previously used `new Date()`,
  which made every deploy claim all six static pages had changed. That is the
  pattern that teaches a crawler to ignore the field. Static pages use the
  `STATIC_UPDATED` constant; guides use their own `updated`.
- **URLs must match the canonical byte for byte**, trailing slash included. A
  sitemap that disagrees with the canonical nominates two URLs for one page.

## 5. Canonicals

Every indexable page sets its own self-referencing canonical via
`alternates.canonical`. There is deliberately **no canonical in the root
layout**: it would be inherited by every page that does not set one, which
previously declared `/contact`, `/privacy` and the rest duplicates of the home
page and kept them out of the index entirely.

The home page canonical is `https://foundervoice.app` with no trailing slash,
and the sitemap matches.

## 6. Metadata

Defaults live in `apps/web/src/app/layout.tsx`; every page overrides `title`
and `description`. The title template is `%s · FounderVoice`.

The home page uses `title: { absolute: … }` so it does not inherit the
template - Google appends the site name to a home page result itself, and the
doubled brand pushed the useful half past the truncation point.

Brand is **FounderVoice**, one spelling, everywhere - exported as `BRAND` from
`apps/web/src/lib/schema.ts`. "FounderVoice AI", "Founder Voice" and
"Foundervoice" competing across titles, schema and footer split one company
into three entities, none of which accumulates what the others earned.

## 7. Structured data

`apps/web/src/lib/schema.ts` holds the shared nodes. The root layout emits
`Organization`, `WebSite` and `SoftwareApplication` in one `@graph`; other
pages reference `Organization` **by `@id`** instead of redeclaring it. That is
the difference between one publisher and eleven look-alikes with the same name.

| Page | Nodes |
|---|---|
| All (root layout) | `Organization`, `WebSite`, `SoftwareApplication` |
| `/guides` | `CollectionPage`, `BreadcrumbList` |
| `/guides/[slug]` | `Article`, `BreadcrumbList`, `FAQPage` |
| `/contact` | `ContactPage` |

Rules:

- The `offers` block mirrors `free_upload_limit` and `free_practice_limit` in
  `apps/api/app/config.py`. It once advertised five recordings while the API
  granted ten. Schema that contradicts the page costs the rich result.
- **No `HowTo`** - deprecated by Google in September 2023.
- `FAQPage` stays, but **expect no SERP feature from it**. Google retired FAQ
  rich results for all sites on 7 May 2026. It is kept because the questions
  are real and it describes the page honestly; do not add it to new pages in
  the hope of a rich result.
- No ratings, no `sameAs`, no founder credentials. Inventing any of them is
  both a policy violation and trivially checkable.

## 8. Guide architecture

All guide content is data in `apps/web/src/lib/guides.ts`, not one file per
page, so the index, sitemap, structured data and cross-links cannot drift.

Page template (`apps/web/src/app/guides/[slug]/page.tsx`):

```
Breadcrumb → H1 → direct answer (intro) → sections → FAQ
          → contextual CTA → related guides
```

The `intro` answers the query in the first paragraph, before any preamble. A
page that makes you scroll past setup to reach what you searched for earns the
bounce it gets.

### Adding a guide

1. Append an object to `GUIDES`. Every field is required; `primaryKeyword` must
   be unique or **the build fails** (see `assertNoDuplicatePrimaries`) - two
   guides sharing a primary compete for one slot and split the signal.
2. Set `cluster` to `speaking` or `founder`. The index groups by it.
3. Name three `related` slugs. `relatedGuides()` backfills from the same
   cluster if you name fewer.
4. Pick a `cta` from the `CTA` map, or add one. It must name the measurement
   the reader came for - a generic "try the product" panel on a filler-words
   page asks someone mid-problem to take an interest in a tour.
5. Set `updated` to today. It drives both the sitemap `lastmod` and the
   `Article` dates.

Nothing else to touch: sitemap, index, llms.txt links and internal linking all
read from the array.

## 9. Internal linking

- Home body links four guides by name plus the index. Before this, `<main>` on
  `/` contained two internal links and no guide at all, which left the only
  organic-acquisition surface with no equity from the front door.
- Every guide links three related guides with **descriptive anchors** - the
  guide title, never "click here" or "read more".
- The guides index groups by cluster so the hub tells a crawler what the
  section is about.
- The 404 links the home page, the guides and a CTA.

## 10. Keyword map

One page, one primary intent. Do not target a primary that is already taken.

### Strategy

Do **not** chase "AI speech coach", "speech coach" or "public speaking". They
are contested by products with years of authority and they describe a category
rather than this product. The home page targets *AI communication coach for
founders*; the guides target long-tail problem and situation queries, which is
where a new domain can actually rank.

`/guides/how-to-improve-english-communication-skills` keeps its English wording
against the founder positioning used everywhere else. That is deliberate: it is
an indexed URL that exists to answer that exact query, and stripping the term
leaves a page with no reason to rank.

## 11. Performance

No web fonts - typefaces resolve from the OS in `globals.css`, because fetching
Inter at build time made every heading fall back to Times New Roman whenever
that fetch failed. Public pages are static, so TTFB is an edge cache hit.

The rule to protect: **public SEO pages must not depend on client rendering.**
`/contact` regressed on exactly this - a `<Suspense fallback={null}>` around a
component reading search params bailed the whole subtree to the client, and
Googlebot received a visually hidden `h1` and an empty `<template>`. Anything a
crawler needs lives outside the boundary, and the fallback renders real markup.

## 12. Analytics

No vendor is wired in - no script, no key, no third-party request.
`apps/web/src/lib/analytics.ts` defines the event names and a `track()` seam;
`AnalyticsBridge` reads `data-fv-event` attributes off CTAs via one delegated
listener. Events queue on `window.fvEventQueue` until something implements
`window.fvAnalytics`.

Events: `guide_view`, `seo_cta_click`, `recording_started`,
`recording_completed`, `analysis_completed`, `signup_completed`.

Only `guide_view` and `seo_cta_click` are emitted today. The recorder events
are defined but not yet called from the record flow.

## 13. Search Console

Manual steps - nothing in this repo can do them:

1. **Verify the domain.** Use a Domain property (covers apex and `www`, http
   and https) via the DNS TXT record. If you use a URL-prefix property instead,
   verify `https://foundervoice.app`.
2. **Submit** `https://foundervoice.app/sitemap.xml`.
3. **Inspect the home page and two guides**, then Request Indexing.
4. **Fix `www` first.** See below - it is currently a different host.
5. Check *Page indexing* weekly for the first month. Expect the nine app routes
   under *Excluded by 'noindex' tag* permanently.

### Pre-flight

```bash
curl -sI https://foundervoice.app/ | grep -i x-robots-tag   # expect nothing
curl -s  https://foundervoice.app/robots.txt
curl -s  https://foundervoice.app/sitemap.xml | head -20
```

## 14. Checklist for a new public page

- [ ] Unique `title` (under ~60 chars including the ` · FounderVoice` suffix)
- [ ] Unique `description` (~150 chars) - **not** inherited from the layout
- [ ] `alternates.canonical`, self-referencing
- [ ] Open Graph title, description, url
- [ ] Exactly one `<h1>`, visible, matching the page subject
- [ ] Content server-rendered - check with
      `curl -A Googlebot <url> | grep -c BAILOUT_TO_CLIENT_SIDE_RENDERING`
- [ ] Added to `sitemap.ts` with a real `lastmod`
- [ ] Linked from somewhere - a page in the sitemap and nowhere else is an
      orphan
- [ ] If it is an app screen, added to `PRIVATE_ROUTES` and **not** the sitemap

## 15. First 30 days

**Week 1 - technical and indexing.** Fix `www` DNS. Verify the Domain
property, submit the sitemap, request indexing on the home page and the guides.
Confirm no public URL returns `X-Robots-Tag`.

**Week 2 - delivery cluster.** The seven speaking guides are live; watch which
pick up impressions first. Expand whichever gets impressions but no clicks -
that is a title and description problem, not a content problem.

**Week 3 - founder cluster.** Four guides live. This cluster has lower volume
and much higher intent, and it is the one the product actually converts. Add
depth where Search Console shows queries you do not have a page for.

**Week 4 - distribution and review.** Guides are not link magnets on their own;
the reference numbers are. Pull the Search Console query report and compare
against the keyword map above - queries landing on the wrong page mean two
pages are competing, which the build check catches for primaries but not for
secondaries.

## Not done yet

Honest list of what this document describes as intended but the repo does not
yet do:

- **`www.foundervoice.app` points at Hostinger, not Vercel**, and serves a PHP
  placeholder page. DNS change, cannot be fixed in code. Do this first.
- **No analytics vendor.** The seam exists; nothing consumes it.
- **`recording_started`, `recording_completed`, `analysis_completed` and
  `signup_completed` are defined but never called.** Wiring them into the
  record flow is what makes guide-to-activation attribution possible.
- **No About page and no named author.** `Article.author` is the Organization.
  A named person with stated experience is the strongest available E-E-A-T
  improvement for advice content, and it needs a real person to attach.
- **No per-guide OG images.** All guides share the generated site card.
- **No Core Web Vitals field data.** Needs a PageSpeed Insights API key or a
  Search Console CrUX export; the payload numbers look good but are not
  measured user experience.
